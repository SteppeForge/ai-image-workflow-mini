# AI Image Workflow Mini

Node-based редактор workflow для AI-генерации изображений: граф из нод (Prompt, Image Input, Generate, Edit, Result) выполняется на backend с параллельными ветками, статусы приходят в UI в реальном времени.

## Запуск

Требуется Node.js ≥ 20.

```bash
npm install
npm run dev
```

- клиент: http://localhost:5173
- сервер: http://localhost:3001

При первом открытии на canvas загружен сценарий с ветвлением (`Prompt → Generate A/B → Result A/B`). Кнопка **«Запустить»** стартует выполнение; обе Generate-ноды работают параллельно, статус запуска — чип в левом верхнем углу canvas, легенда типов портов — в правом.

AI-генерация реальная (Pollinations.AI, модель FLUX) и **работает без API-ключа** — ничего настраивать не нужно. На анонимном тарифе действует лимит ~1 запрос / 15 с: при параллельных ветках вторая дольше остаётся в `running` и автоматически повторяется после паузы. Опциональный ключ повышает лимиты — см. ниже.

Тесты и проверка типов:

```bash
npm test          # тесты обоих пакетов (Vitest): executor, валидация графа, HTTP API, клиентская логика
npm run typecheck # strict TypeScript во всех трёх пакетах
```

Покрытие по слоям: ядро executor (параллелизм, зависимости, retry, изоляция упавшей ветки), валидация графа (включая недоверенный JSON и prototype-ключи), HTTP-контракты через `fastify.inject` (без сети), на клиенте — валидация соединений (typed ports, циклы, занятые порты), маппинг canvas → graph definition и гонки запуска (устаревший ответ `POST /runs` не перетирает новый запуск). Браузерного e2e (Playwright) нет осознанно: для тестового это плюс час работы и сотни мегабайт браузеров ради проверок, которые уже закрыты на уровне логики и API.

## Демо возможностей

| Что проверить | Как |
|---|---|
| Параллельное выполнение | Run на branching-демо: обе Generate-ноды одновременно в `running` |
| Error state + retry | В режиме `IMAGE_PROVIDER=mock`: дописать `[fail]` в текст промпта → нода упадёт → кнопка **Retry** на ноде. Ретрай `[fail]`-ноды честно падает вновь (граф запуска иммутабелен) — механизм рассчитан на транзиентные ошибки реального API (таймаут, rate limit) |
| Typed ports | Попытаться соединить синий порт (text) с зелёным (image) — соединение блокируется |
| Сценарий 1 и 2 | Кнопки «Сценарий 1 / Сценарий 2 / Ветвление» в тулбаре |
| Статус запуска | Постоянный чип в левом углу canvas: `run: idle` до первого запуска → `queued/running/completed/failed`; плавает над графом, не сдвигает вёрстку |
| Обрыв SSE | Остановить сервер во время запуска: клиент автоматически переходит на последовательный опрос `GET /runs/:runId` (пометка в чипе; запросы не накладываются, устаревший ответ не перетирает свежий SSE-снапшот), а если run пропал после рестарта — показывает «запуск потерян» и разблокирует новый запуск |
| Повторный запуск | Кнопка «Запустить» заблокирована, пока текущий запуск выполняется — второй параллельный run конкурировал бы с первым за rate-limit провайдера. Рядом появляется «Стоп» — выход из отслеживания без сброса графа (даже если сеть легла целиком; серверные jobs при этом довыполняются — отмены на сервере нет, это осознанное упрощение) |
| Undo / Redo | `Ctrl+Z` / `Ctrl+Shift+Z` (или `Ctrl+Y`) либо кнопки ↩/↪ — история структурных правок графа (текст в полях — нативный undo браузера) |
| Разрыв соединения | Кнопка **×** посередине ребра (или выделить ребро и `Delete`); отменяется через `Ctrl+Z` |
| Ветвление вручную | От одного выхода можно протянуть сколько угодно связей (1 Промпт → N Генераций), вход же принимает ровно одну |
| Скачивание результата | Кнопка **↓** на картинке в Result-ноде; имя файла с верным расширением приходит с сервера (`Content-Disposition`) |
| Сброс | Возвращает к тому демо, из которого вырос текущий граф (активное демо подсвечено в тулбаре), а не всегда к ветвлению |
| Защита во время запуска | Пока run выполняется, удаление нод и рёбер заблокировано — кнопками, клавишами и undo/redo (иначе с экрана пропадали бы живые статусы); добавление и редактирование доступны. Блокировка включается с момента отправки `POST /runs`, а не с получения `runId` — из зависшего запроса тоже есть выход через «Стоп» |
| Язык интерфейса | Переключатель RU/EN в шапке (по умолчанию русский). Лёгкий словарь без библиотек; статусы job/run намеренно не переводятся — это словарь ТЗ, общий с API |
| Миникарта | Цвета по типам нод; скрывается/показывается кнопкой в панели зума (слева внизу) |
| Адаптивность | Тулбар меняет раскладку трижды: до 900px — меню «Добавить»/«Демо»; 900–1279px — свитч режима (видна одна группа кнопок из двух, переключение анимировано); от 1280px — полный ряд. Кнопка запуска — иконка, подпись добавляется только от 1440px. Миникарта скрыта на узких экранах; canvas управляется тачем (React Flow) |
| Валидация графа сервером | Запустить граф без соединений — сервер вернёт список ошибок, они показываются под тулбаром |

## Стек и почему он

| Слой | Выбор | Причина |
|---|---|---|
| Frontend | React 19 + TypeScript + Vite | FSD и React Flow — конвенции React-экосистемы, заданные ТЗ |
| Canvas | @xyflow/react (React Flow 12) | Рекомендован ТЗ; писать canvas engine с нуля не требуется |
| Состояние | Zustand | Лёгкий, хранит модель графа вне UI-компонентов (требование FSD) |
| Стили | Tailwind CSS 4 | Скорость вёрстки без собственной дизайн-системы |
| Backend | Fastify 5 + TypeScript | Нативный TS, минимум кода, встроенный логгер |
| AI API | Pollinations.AI (FLUX) | Работодатель разрешил «ключи из открытых источников»; работает без ключа и регистрации — ревьюер запускает проект без настройки |
| Тесты | Vitest | Executor и валидация покрыты без поднятия HTTP |
| Монорепо | npm workspaces: `client` / `server` / `shared` | `shared` — единый источник типов контрактов для обеих сторон |
| UI-примитивы | Свои (Button, Select, DropdownMenu, StatusBadge, ConfirmDialog, Spinner, InfoHint) | Тянуть UI-библиотеку ради нескольких контролов — лишние зависимости |

## Архитектура

Подробности и решения: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

Коротко:

- **Graph definition — это данные** (`shared/src/graph.ts`): ноды, рёбра, типизированные порты. Canvas — только редактор этих данных; сервер выполняет граф, не зная про React Flow.
- **Executor** (`server/src/core/executor.ts`) — событийный: нода стартует, как только все её зависимости в `success`. Независимые ветки запускаются в одном тике без ожидания друг друга — это и есть параллелизм.
- **Статусы** — два словаря, как в ТЗ: job `idle/queued/running/success/error`, run `queued/running/completed/failed`. `idle` — состояние ноды до первого запуска (на сервере job сразу `queued`).
- **Preset** — отдельная сущность data model (`server/src/core/presets.ts`); Request Builder склеивает user prompt + `mainPrompt` + `negativePrompt` + `references` в запрос провайдеру.
- **API-ключ не попадает во frontend**: клиент ходит только на свой backend через Vite-proxy `/api`; ключ живёт в `server/.env`.

## API

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/runs` | Создать запуск: `{ graph }` → `201 { runId }`; `400 { errors[] }` при невалидном графе |
| `GET` | `/runs/:runId` | Снапшот запуска (статусы run и jobs) — polling; клиент использует его как fallback при обрыве SSE |
| `GET` | `/runs/:runId/events` | То же живым SSE-потоком; после `completed` сервер закрывает поток (`failed` остаётся открыт для retry) |
| `POST` | `/runs/:runId/nodes/:nodeId/retry` | Повтор упавшей ноды (`404` — run/нода не найдены, `400` — нода не в `error`) |
| `GET` | `/presets` | Каталог пресетов |
| `GET` | `/images/:id` | Сгенерированные/загруженные картинки (в снапшотах — лёгкие ссылки, не base64) |
| `GET` | `/references/:file` | Референсы пресетов |
| `GET` | `/health` | Проверка живости |

## AI-провайдер

Провайдер выбирается через `IMAGE_PROVIDER` в `server/.env` (см. `server/.env.example`):

- **`pollinations`** (по умолчанию) — реальная генерация через [Pollinations.AI](https://pollinations.ai), модель FLUX. Ключ не обязателен. Опциональный `POLLINATIONS_API_KEY` (бесплатная регистрация на enter.pollinations.ai → Keys → Secret key `sk_...`):
  - поднимает rate limit (анонимно ~1 запрос / 15 с; при параллельных ветках вторая автоматически повторяется после паузы);
  - включает **реальное редактирование** (модель kontext, endpoint `/v1/images/edits`). Ключ живёт только в `server/.env` и не попадает во frontend. `server/.env` игнорируется git; при передаче проекта архивом файл нужно исключить вручную.
- **`mock`** — офлайн-разработка и демо без сети: имитирует задержку, рисует SVG с текстом промпта; `[fail]` в тексте триггерит ошибку для демонстрации retry.

Маппинг полей Request Builder → Pollinations: `prompt` — как есть; `negativePrompt` — вклеивается в текст промпта (`Avoid: ...`), у открытого endpoint нет отдельного параметра; `references` — txt2img-endpoint их не принимает, поле остаётся в модели и передаётся провайдеру (адаптер использует то, что поддерживает API); сами файлы референсов сервер отдаёт по `GET /references/<file>`. Ответы провайдера (и генерация, и редактирование) проверяются одинаково: только растровые форматы (внешний SVG мог бы нести активное содержимое), лимит размера проверяется потоково во время скачивания; url-результат редактирования скачивается сервером только с https-хостов `*.pollinations.ai` без redirect (защита от SSRF) и хранится как обычная картинка — внешние URL в снапшоты не попадают.

**Edit Image**: нода и граф работают полностью. Без `POLLINATIONS_API_KEY` нода падает с понятной ошибкой `Image editing requires POLLINATIONS_API_KEY` — подход, предусмотренный ТЗ: интерфейс `ImageProvider.supportsEdit` + метод `editImage`, реализация подключается без изменения executor и UI.

## Roadmap (за рамками тестового)

Фичи, осознанно отложенные, чтобы остаться в лимите 8–12 часов и не размывать ядро:

- светлая тема (требует ревизии палитры всех компонентов);
- TTL/очистка runs и картинок, очереди и персистентность (см. ARCHITECTURE).

Граф на canvas сохраняется в localStorage — обновление страницы не теряет правки (загруженные через Image Input картинки намеренно не сохраняются: многомегабайтные data URL не помещаются в квоту localStorage). Кнопка **Сброс** возвращает canvas к тому демо, из которого вырос текущий граф (с подтверждением) — выбрали «Сценарий 1», поредактировали, сбросили → снова «Сценарий 1».

## Статус и недоделанное

- Осознанные упрощения тестового: runs и картинки в памяти процесса (перезапуск сбрасывает), без персистентности и очередей. Границы и продакшен-альтернативы: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md#осознанные-упрощения).
- Редактирование на реальном API требует ключа (проверено с ключом: kontext редактирует загруженное изображение по инструкции end-to-end); без ключа сценарий 2 демонстрируется на `IMAGE_PROVIDER=mock` либо нода Edit показывает обработку ошибки провайдера.
