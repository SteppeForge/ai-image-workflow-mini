# Архитектура

## Монорепо

```
shared/   типы контрактов: граф, порты, статусы, пресеты, API
server/   Fastify: валидация графа, executor, провайдеры, runs API
client/   React: FSD, canvas на React Flow, SSE-подписка
```

`shared` — buildless-пакет (TS-исходники импортируются напрямую): клиент и сервер физически не могут разойтись в контрактах. Пример: `NODE_PORTS` — спецификация портов каждой ноды — одна на всех; клиент по ней блокирует несовместимые соединения при drag, сервер по ней же валидирует граф при `POST /runs`.

## Frontend: FSD

```
client/src/
├── app/        точка входа, глобальные стили, сидинг демо-графа при первом открытии
├── pages/
│   └── editor/ компоновка страницы, хоткеи undo/redo, переключатель RU/EN
├── widgets/
│   ├── workflow-canvas/  React Flow + NodeShell + 5 нод; ребро с кнопкой разрыва, чипы статуса и легенды, миникарта
│   └── toolbar/          добавление нод, демо, undo/redo, Reset, запуск; мобильные меню
├── features/
│   └── run-workflow/     запуск графа, SSE-подписка с polling-fallback, retry ноды
├── entities/
│   ├── workflow/  модель графа (Zustand: undo/redo-стеки, persist), валидация соединений, демо-графы
│   ├── run/       снапшот текущего запуска (Zustand), бейдж job-статуса, чип run-статуса
│   └── preset/    загрузка каталога пресетов (кэш на сессию)
└── shared/
    ├── api/   fetch-обёртка, ApiError, resolveImageUrl
    ├── i18n/  словарь RU/EN без библиотек (статусы job/run не переводятся — словарь ТЗ)
    ├── lib/   use-dismissable (закрытие попапов), storage (localStorage без исключений: приватный режим, квота, тесты)
    └── ui/    Button, Spinner, StatusBadge, ConfirmDialog, Select, DropdownMenu, InfoHint
```

Направление импортов сверху вниз (app → pages → widgets → features → entities → shared), бизнес-логики в UI-компонентах нет: модель графа и статусы живут в Zustand-сторах слоя entities; запуск и SSE-подписка — в feature-хуке `use-run-workflow`, retry ноды — отдельный feature-action `retry-node.ts` (его зовёт кнопка на ноде).

История атомарна по пользовательскому действию: React Flow при удалении связанной ноды клавишей шлёт два пакета изменений подряд (сначала рёбра, потом ноду), поэтому снимки одного тика схлопываются в один — иначе первый undo возвращал бы ноду без её связей.

Стор графа помнит демо-шаблон, из которого вырос текущий граф (`activeDemoKey`) — именно туда возвращает «Сброс», и по нему же подсвечивается активное демо в тулбаре. Также стор держит undo/redo-стеки структурных правок (набор текста в историю не пишется — у полей свой нативный undo) и сохраняется в localStorage через дебаунс-адаптер (запись раз в 300 мс + flush на beforeunload): React Flow эмитит position-изменения на каждый кадр drag’а, сериализовать граф синхронно на каждый нельзя.

`NodeShell` — общая обёртка всех пяти нод: заголовок, live-статус job, порты (рендерятся из `NODE_PORTS`), кнопки удаления и Retry при ошибке. Ноды содержат только свои поля ввода.

Соединения рвутся кнопкой на ребре: `DeletableEdge` подменяет встроенный тип `default`, поэтому кнопка есть и у демо-рёбер; клик по тонкой кривой неочевиден, а `delete` для canvas требует ТЗ. Штатное оттягивание конца связи (`edgesReconnectable`) отключено осознанно: зона порта и конец провода геометрически накладываются, и жест перехватывал создание новой связи — предсказуемость порта важнее удобства «переткнуть не пересоздавая». На время запуска удаление нод и рёбер отключается: иначе с экрана исчезали бы живые статусы выполняющихся job (сам запуск на сервере от этого не зависит — граф запуска иммутабелен).

### UI-инварианты

- **No layout shift**: смена состояния не двигает вёрстку: статус запуска и легенда портов — плавающие чипы над canvas, ошибки валидации — overlay под тулбаром, шапка и тулбар не меняют высоту от состояний.
- **Адаптивность — три раскладки тулбара.** Полному ряду нужно около 1300px, поэтому одного встроенного порога `md` (768px) не хватало: на планшетах кнопки рассыпались в две-три строки. Добавлены свои точки (`@theme` в `app/index.css`): `tablet` 900px и `wide` 1440px.
  - **до 900px** — обе группы свёрнуты в `DropdownMenu`;
  - **900–1279px** — `SegmentedSwitch` переключает «Добавить»/«Демо»: одна группа кнопок видна целиком и доступна в один клик, вторая уезжает с анимацией (обе остаются в разметке, высота зафиксирована — вёрстка не прыгает);
  - **от 1280px** — полный ряд. Подпись у кнопки запуска появляется только с 1440px — раньше она ломала строку; до этого кнопка иконочная, название живёт в `aria-label` и tooltip.

  Миникарта скрыта на узких экранах; canvas — тач-управление React Flow.
- **Один язык чипов**: статус и легенда оформлены одинаково (rounded-md чип с точкой-индикатором) и симметричны по углам canvas.
- **Движение только осмысленное**: всплывающие панели появляются за 130 мс (прозрачность + сдвиг 4px) в пару к уже анимированной стрелке; закрытие — без анимации (не стоит лишнего состояния в компоненте), `prefers-reduced-motion` уважается.

## Backend

```
server/src/
├── app.ts                 маршруты (фабрика — тестируема без сети)
├── index.ts               bootstrap
├── core/
│   ├── graph.ts           валидация: форма JSON, порты, типы, циклы, лимиты
│   ├── executor.ts        RunManager: выполнение графа
│   ├── image-store.ts     in-memory хранилище картинок (/images/<id>)
│   ├── presets.ts         каталог пресетов (in-memory)
│   └── request-builder.ts user prompt + preset → запрос провайдеру
├── providers/
│   ├── types.ts           интерфейс ImageProvider
│   ├── pollinations.ts    реальный API: FLUX-генерация + kontext-редактирование
│   ├── mock.ts            офлайн-мок для разработки и тестов
│   └── index.ts           выбор по IMAGE_PROVIDER
└── assets/references/     файлы референсов пресетов (GET /references/<file>)
```

### Выполнение графа

1. `POST /runs` → валидация → `RunState`: jobs всех нод в `queued`, run `queued`.
2. `tick()`: запустить каждую `queued`-ноду, у которой все зависимости `success`. Запуски не ожидаются (`void launch(...)`) — независимые ветки выполняются одновременно.
3. Завершение любой ноды → снова `tick()`. Так волна доходит до конца графа.
4. Run: `completed`, когда все jobs `success`; `failed`, когда есть `error` и ничего не выполняется.

Каждое изменение эмитится в `EventEmitter` запуска → SSE-поток `GET /runs/:runId/events`. После `completed` сервер закрывает поток (такой run уже не изменится), `failed`-поток остаётся открыт для retry. Обычный `GET /runs/:runId` — polling: клиент автоматически переходит на него при обрыве SSE. Опрос последовательный (следующий запрос — только после ответа предыдущего), а при восстановлении SSE активная polling-сессия инвалидируется — запоздавший ответ не перетрёт свежий SSE-снапшот. Состояние связи видно в чипе статуса; пропавший после рестарта run помечается «потерянным» и разблокирует новый запуск. На время выполнения в тулбаре доступен «Стоп» — клиентский выход из отслеживания без сброса графа (отмены jobs на сервере нет — осознанное упрощение).

### Retry

Ошибка ноды не трогает соседние ветки: их jobs доходят до конца. Downstream-ноды упавшей остаются в `queued` — они «ждут выполнения». `POST .../retry` переводит упавшую ноду `error → queued`, run `failed → running`, и `tick()` продолжает с места падения. Повторно выполняется только упавшая нода и её downstream; успешные результаты не пересчитываются.

### Таймауты и ошибки

Вызов провайдера получает `AbortSignal.timeout(IMAGE_TIMEOUT_MS)` (по умолчанию 120 с — запас на паузу ретрая при rate-limit). Любая ошибка (таймаут, сеть, ответ API) становится `error` конкретной job с человекочитаемым сообщением — оно показывается прямо на ноде.

### Провайдеры

`ImageProvider` — единственная точка интеграции с внешним AI API: `generateImage`, `editImage`, флаг `supportsEdit`. Реализации:

- `PollinationsProvider` — реальная генерация (FLUX) через открытый endpoint без ключа; при 429/5xx один повтор после паузы с учётом `Retry-After` (анонимный rate limit ~1 запрос / 15 с). Редактирование — kontext через `gen.pollinations.ai`, требует ключ, поэтому `supportsEdit` вычисляется из наличия `POLLINATIONS_API_KEY`.
- `MockProvider` — офлайн-разработка и тесты; `[fail]` в тексте триггерит ошибку.

Провайдер возвращает URL или байты; байты и data-URL executor кладёт в `ImageStore` (in-memory), загруженные через Image Input картинки тоже сохраняются туда при выполнении ноды — в снапшоты и SSE всегда попадают лёгкие ссылки `/images/<id>` вместо base64. Ответ внешнего API проверяется для генерации и редактирования одинаково: только растровые content-type (png/jpeg/webp/gif — внешний SVG мог бы нести скрипты), лимит размера проверяется потоково при чтении (не после загрузки всего тела в память), url-результат редактирования скачивается сервером только с https-хостов `*.pollinations.ai` и без redirect — защита от SSRF (внешние URL не утекают в снапшоты), отдача клиенту с `nosniff`. Ключ — только в `server/.env`.

Тексты ошибок API и валидации — английские и не локализуются: это контракт сервера, а не UI-текст (словарь i18n клиента их не переводит).

Граница HTTP считает вход недоверенным: `validateGraph` проверяет не только семантику (порты, циклы), но и форму JSON — типы полей, лимиты количества нод/рёбер и длины текстов, безопасный алфавит id (заодно исключающий prototype-polluting ключи вроде `__proto__`; снапшоты дополнительно собираются на объекте без прототипа).

## Осознанные упрощения

Границы тестового, зафиксированные сознательно:

| Упрощение | Причина | Что делать в продакшене |
|---|---|---|
| Runs в памяти процесса | Персистентность не требуется ТЗ | БД + очередь задач (например, Postgres + BullMQ) |
| Картинки в `ImageStore` в памяти | Нет файлового хранилища | Object storage (S3), отдача через CDN |
| SSE без heartbeat и Last-Event-ID (есть: закрытие потока после `completed`, авто-reconnect браузера, polling-fallback клиента) | Снапшоты самодостаточны — потеря промежуточного события не ломает состояние | Heartbeat против idle-прокси, Last-Event-ID, лимит подписчиков, backpressure |
| Runs и картинки не очищаются до перезапуска процесса | TTL/LRU — лишняя механика для тестового | TTL + LRU либо вынос в БД/object storage |
| Один процесс сервера | In-memory EventEmitter | Pub/sub (Redis) при горизонтальном масштабировании |
| Референсы пресетов — пути-строки | Формат вложения зависит от выданного API | По документации реального API |
